## 第一层：产品定义

### 1.1 这是什么

一个开源、本地部署、单人使用的 TikTok 跨境电商 AI 运营工作台。核心是一个具备领域知识、长期记忆和持续学习能力的 Agent（AI 智能助手），卖家通过自然语言对话完成选品调研、商品文案与素材生成、内容策划与脚本创作、店铺运营优化四类工作。数据全部存在卖家自己的电脑上。

术语说明：
- 开源：源代码公开，任何人可下载和修改。
- 本地部署：软件跑在用户自己的电脑上，而不是服务商的服务器上。
- 自然语言：人平时说话写字的语言，用户不用学任何命令，直接说需求即可。
- API Key：向 AI 服务商购买调用额度时拿到的一串密钥文本，程序用它证明你有权调用模型，费用按实际调用量结算。

### 1.2 给谁用

**独立 TikTok 跨境卖家**。自己有一台电脑，会双击打开软件、会在网页上填写 API Key，但不会也不想使用命令行。每天用它辅助选品、写文案、做内容规划。

不面向：团队、企业、代运营公司、多人协作场景。不设"技术型用户"这一档，产品功能不为二次开发者设计；开源只意味着代码可以自己改。

### 1.3 做什么（本版本全部范围）

本产品只有一个版本，一次性实现并交付以下全部功能，不分迭代、不分优先级：

1. 部署与首次使用：Windows / macOS / Linux 三个启动脚本，双击即用；浏览器引导页填 API Key；引导创建第一个店铺。
2. AI 对话中枢：流式对话、历史对话列表、全局侧边抽屉、工具调用过程可见、快捷指令。
3. 选品调研：市场分析、竞品分析、选品方向推荐。
4. 商品文案与素材：多语言文案生成、反馈修改、文案版本历史、SKU 管理、商品主图与详情图生成、图片变体。
5. 内容策划：视频分镜脚本（含钩子与 CTA）、风格模仿、直播流程脚本。
6. 店铺运营优化：数据解读与诊断建议、综合运营建议、领域知识问答、合规免责提示。
7. 多店铺工作台：添加 / 编辑 / 归档店铺、快速切换、店铺间数据完全隔离、一键导出 Excel 备份。
8. 记忆体系：对话内短期记忆、跨对话长期记忆（店铺画像与用户偏好）、数据库辅助记忆（查询历史业务数据）、记忆查看 / 编辑 / 删除。
9. 自我迭代：Agent 沉淀可复用技能（创建前征求确认）、技能管理、偏好学习与查看。

### 1.4 明确不做什么（与"做什么"同等重要）

- 不做账号体系：无注册、无登录、无密码、无权限管理、无 OAuth。
- 不做多人协作：无团队、无邀请、无成员角色、无共享。
- 不做云端托管：不提供 SaaS 服务，不托管任何用户数据。
- 不做多平台：只服务 TikTok 跨境电商，不做 Amazon、Shopee、独立站等。
- 不做 TikTok Shop 官方 API 对接：不读写卖家的 TikTok 店铺后台数据。
- 不做广告投放管理。
- 不做智能定价。
- 不做供应链对接。
- 不做多 Agent 协作。
- 不做插件市场。
- 数据库不用 PostgreSQL：只用本地 SQLite 单文件。

## 第二层：用户故事列表

以下每一条用户故事都附带验收标准。验收标准是交付验收时的检查清单，逐条对照，全部满足才算该功能完成。

### 2.1 部署与首次使用

**用户故事 1：一键启动**
作为独立卖家，我想要双击启动脚本就能打开工作台，以便我不需要学习任何命令行操作。

验收标准：
- Windows 提供 `启动.bat`，macOS 提供 `启动.command`，Linux 提供 `start.sh`，双击即可运行
- 脚本自动完成环境检测、依赖安装、服务启动、打开浏览器
- 从首次启动到进入工作台，全程无需打开终端、无需输入任何命令
- 90% 的用户能在 10 分钟内完成首次部署并开始使用

**用户故事 2：配置 API Key**
作为独立卖家，我想要在浏览器引导页填写我的 API Key，以便工作台能调用 AI 模型，而不需要我手动编辑配置文件。

验收标准：
- 首次打开 localhost:3000 时若未配置 Key，自动进入引导页
- 引导页提供填写框和"如何获取 API Key"的说明链接
- 保存后写入服务端本地配置，前端浏览器无法读取该 Key
- 之后每次启动不再出现该引导页

**用户故事 3：创建第一个店铺**
作为独立卖家，我想要在首次使用时创建我的第一个店铺，以便后续所有工作都基于这个店铺。

验收标准：
- 数据库中无店铺时自动进入店铺创建引导
- 表单包含：店铺名称（必填）、所属市场（下拉选择）、店铺简述（选填）
- 创建成功后进入工作台，Agent 自动打招呼，招呼语中包含店铺名和市场

### 2.2 AI 对话中枢

**用户故事 4：新建对话**
作为独立卖家，我想要新建对话与 Agent 讨论运营话题，以便每个话题独立进行、互不干扰。

验收标准：
- 点击"新建对话"进入空白对话界面
- 输入消息后收到 Agent 流式回复

**用户故事 5：历史对话列表**
作为独立卖家，我想要查看历史对话列表，以便随时继续之前的话题。

验收标准：
- 左侧展示当前店铺的对话列表，按时间倒序排列
- 每项显示标题和最后活跃时间

**用户故事 6：全局侧边抽屉**
作为独立卖家，我想要在任何页面从右下角唤出 Agent，以便不离开当前页面就能提问。

验收标准：
- 所有页面右下角有 Agent 入口
- 点击后从右侧滑出对话面板，当前页面不跳转

**用户故事 7：流式输出**
作为独立卖家，我想要 Agent 的回复逐字出现，以便不用等全部生成完就能开始阅读。

验收标准：
- 回复以打字机效果逐字显示
- 不是等全部生成完毕才一次性显示

**用户故事 8：工具调用可见**
作为独立卖家，我想要看到 Agent 调用工具的过程，以便我知道它正在做什么。

验收标准：
- 调用工具时显示状态卡片（如"正在分析选品数据……"）
- 工具完成后展示结构化结果

**用户故事 9：快捷指令**
作为独立卖家，我想要点击快捷指令按钮触发常用操作，以便不用每次都打字。

验收标准：
- 输入框上方提供"生成文案""写脚本""选品分析""数据解读"按钮
- 点击按钮后 Agent 调用对应工具完成操作

**用户故事 10：自然语言驱动业务操作**
作为独立卖家，我想要用自然语言让 Agent 做业务操作，以便不用学习任何界面操作流程。

验收标准：
- 例："分析一下宠物用品在美区的机会" → Agent 调用选品工具并返回结构化报告

**用户故事 11：店铺上下文感知**
作为独立卖家，我想要 Agent 知道我在哪个店铺、卖什么、面向哪个市场，以便不用每次都重复介绍店铺信息。

验收标准：
- 回答自动基于当前店铺上下文
- 切换到店铺 B 后新建对话，Agent 的上下文完全是店铺 B 的

**用户故事 12：记住偏好**
作为独立卖家，我想要 Agent 记住我说过的偏好和习惯，以便后续生成内容时自动应用。

验收标准：
- 说过"我喜欢简洁的标题"后，后续生成的文案自动应用该偏好

### 2.3 选品调研

**用户故事 13：市场分析**
作为独立卖家，我想要 Agent 分析某个品类在目标市场的机会，以便用数据代替凭感觉选品。

验收标准：
- 输入品类关键词和目标市场
- Agent 通过 MCP 数据平台获取数据
- 输出结构化报告，包含：市场容量、竞争度、增长趋势、利润空间

**用户故事 14：选品方向推荐**
作为独立卖家，我想要 Agent 基于数据推荐选品方向，以便知道下一步该选什么品。

验收标准：
- 基于市场数据 + 店铺定位 + 历史销售数据给出推荐
- 每个推荐都有数据支撑和理由

**用户故事 15：竞品分析**
作为独立卖家，我想要 Agent 拆解竞品的运营策略，以便找出自己的差异化打法。

验收标准：
- 输入竞品信息后，Agent 分析定价策略、内容风格、上新频率、流量结构
- 报告末尾包含"与你的店铺对比"和"建议的差异化方向"

### 2.4 商品文案与素材

**用户故事 16：完整上架文案**
作为独立卖家，我想要 Agent 为商品生成完整上架文案，以便直接用于上架。

验收标准：
- 输入商品信息，生成标题、描述、卖点、利益点
- 标题符合 TikTok Shop 字符限制

**用户故事 17：市场语言适配**
作为独立卖家，我想要文案自动适配目标市场的语言和文化，以便不同站点都能直接使用。

验收标准：
- 美区生成英文，突出 free shipping 和 reviews
- 东南亚按目标国家语言生成

**用户故事 18：反馈修改**
作为独立卖家，我想要对文案提出反馈让 Agent 修改，以便迭代出满意的版本。

验收标准：
- 例："标题太长了" → Agent 基于反馈生成新版本

**用户故事 19：文案历史**
作为独立卖家，我想要查看商品的所有历史文案版本，以便对比和回溯。

验收标准：
- 商品详情页"文案历史"标签页列出所有版本
- 支持版本对比和切换

**用户故事 20：SKU 编码规则**
作为独立卖家，我想要 Agent 建议 SKU 编码规则，以便统一商品的编码方式。

验收标准：
- 基于品类和已有 SKU 模式生成编码方案

**用户故事 21：批量变体 SKU**
作为独立卖家，我想要 Agent 批量生成变体 SKU，以便颜色尺寸组合多时不用手工枚举。

验收标准：
- 输入变体组合（颜色 × 尺寸），批量生成 SKU 列表

**用户故事 22：商品主图生成**
作为独立卖家，我想要 Agent 生成商品主图，以便省去设计成本。

验收标准：
- 基于商品信息和目标市场审美偏好生成主图

**用户故事 23：详情图序列**
作为独立卖家，我想要 Agent 生成商品详情图，以便详情页完整展示卖点。

验收标准：
- 生成包含卖点、场景展示、参数信息的详情图序列

**用户故事 24：图片变体**
作为独立卖家，我想要基于已有图片生成变体，以便一张图用于多个场景。

验收标准：
- 上传图片后生成不同背景 / 场景的变体

### 2.5 内容策划

**用户故事 25：分镜脚本**
作为独立卖家，我想要 Agent 写视频分镜脚本，以便照着拍视频。

验收标准：
- 指定商品、类型（开箱 / 教程 / 种草 / 对比）、时长
- 生成每个镜头的画面描述、口播、字幕、时长

**用户故事 26：钩子与 CTA**
作为独立卖家，我想要脚本自带钩子和 CTA，以便提升视频的完播率和转化率。

验收标准：
- 前 3 秒有钩子文案
- 结尾有行动号召

**用户故事 27：风格模仿**
作为独立卖家，我想要 Agent 模仿某个表现好的视频风格，以便复用成功的套路。

验收标准：
- 描述一个视频风格后，Agent 模仿其结构和节奏生成脚本

**用户故事 28：直播流程脚本**
作为独立卖家，我想要 Agent 写直播流程脚本，以便开播时有序进行。

验收标准：
- 指定时长和商品列表
- 生成开场、讲解顺序、互动、促销节奏

### 2.6 店铺运营优化

**用户故事 29：数据解读**
作为独立卖家，我想要 Agent 解读运营数据，以便发现店铺的问题。

验收标准：
- 手动输入或上传指标，Agent 诊断问题并给出优化建议

**用户故事 30：建议具体可执行**
作为独立卖家，我想要优化建议具体可执行，以便拿到就能直接照做。

验收标准：
- 格式示例："你的完播率（15%）低于均值（25%），建议：1. 前 3 秒加悬念钩子 2. 时长缩短至 30 秒……"

**用户故事 31：数据看板**
作为独立卖家，我想要一个数据看板，以便一眼看到关键指标。

验收标准：
- 展示 GMV、订单量、转化率、流量来源、内容表现等指标
- 数据来源：FastMoss MCP 实时查询，不落库存储

**用户故事 32：综合运营建议**
作为独立卖家，我想要 Agent 给出综合运营建议，以便知道下一步做什么。

验收标准：
- 综合店铺数据、市场趋势、竞品动态、平台规则变化
- 给出分阶段建议

**用户故事 33：领域知识问答**
作为独立卖家，我想要问任何跨境电商运营问题，以便不用自己到处查资料。

验收标准：
- 基于内置领域知识回答平台规则、物流、关税、VAT、合规等问题

**用户故事 34：合规免责提示**
作为独立卖家，我想要合规类问题的答案带免责提示，以便知道答案仅供参考。

验收标准：
- 涉及法律、税务、知识产权时提供参考，同时标注"建议咨询专业人士"

### 2.7 多店铺工作台

**用户故事 35：店铺管理**
作为独立卖家，我想要添加和管理多个店铺，以便一个人管理多家店。

验收标准：
- 设置中可添加店铺（名称、市场、描述）
- 支持编辑和归档店铺

**用户故事 36：快速切换店铺**
作为独立卖家，我想要在工作台顶部快速切换店铺，以便不用进入设置页操作。

验收标准：
- Header 中的下拉切换器展示所有店铺
- 切换后全局数据刷新

**用户故事 37：数据完全隔离**
作为独立卖家，我想要店铺之间的数据完全隔离，以便不会把两家店的数据搞混。

验收标准：
- 店铺 A 的商品、内容、对话、记忆不会出现在店铺 B 的任何界面中
- 在店铺 A 的对话中不会引用店铺 B 的商品或数据

**用户故事 38：数据导出**
作为独立卖家，我想要一键导出工作台数据，以便备份和迁移。

验收标准：
- 设置中一键导出为 Excel 文件
- SQLite 文件本身也可以直接作为备份

### 2.8 记忆体系

**用户故事 39：对话内短期记忆**
作为独立卖家，我想要 Agent 正确理解对话中的指代，以便多轮讨论不丢失上下文。

验收标准：
- "按照刚才第二个方案继续"等指代能被正确理解
- 上下文超限时自动压缩，保留关键信息

**用户故事 40：跨对话记住店铺信息**
作为独立卖家，我想要 Agent 跨对话记住店铺信息，以便不用每次重复交代。

验收标准：
- 说过"我们主打 25-35 岁女性"后，后续所有文案和建议自动考虑该定位

**用户故事 41：自动学习偏好**
作为独立卖家，我想要 Agent 从反馈中自动学习偏好，以便越用越顺手。

验收标准：
- 多次要求缩短标题后，Agent 自动记住"偏好短标题"

**用户故事 42：主动告知学到了什么**
作为独立卖家，我想要 Agent 告诉我它学到了什么，以便我知道记忆在生效。

验收标准：
- 例："我注意到你总是要求提到免运费，我已经记住了"

**用户故事 43：管理记忆**
作为独立卖家，我想要查看、编辑、删除 Agent 的记忆，以便纠正它记错的内容。

验收标准：
- 设置页"Agent 记忆"板块分类展示记忆
- 支持编辑和删除

**用户故事 44：查历史业务数据**
作为独立卖家，我想要 Agent 查询店铺的历史数据，以便不用自己翻记录。

验收标准：
- "上季度新上了几个品" → Agent 查数据库后准确回答
- "上个月写了哪些脚本" → 列出历史视频脚本

**用户故事 45：参考历史优化生成**
作为独立卖家，我想要 Agent 生成内容时参考历史高表现内容，以便产出越来越好。

验收标准：
- 生成文案时自动参考历史高表现文案的风格

### 2.9 自我迭代

**用户故事 46：技能沉淀**
作为独立卖家，我想要 Agent 把重复出现的操作模式沉淀为技能，以便以后一键复用。

验收标准：
- 多次做同类操作后，Agent 提出创建可复用的技能
- 我确认后技能才创建

**用户故事 47：技能管理**
作为独立卖家，我想要管理 Agent 的技能，以便控制它使用哪些技能。

验收标准：
- 设置中查看、启用、禁用、删除技能

**用户故事 48：偏好查看**
作为独立卖家，我想要问 Agent 它对我了解多少，以便确认它记住的偏好是否正确。

验收标准：
- "你对我了解多少" → Agent 列出所有记住的偏好

## 第三层：数据对象描述

系统中有以下核心对象（业务概念，不涉及具体字段类型；数据库设计由开发时据此翻译）：

- 店铺（Shop）：系统的隔离单元。有名称、所属市场、简述。一个部署可以有多个店铺，所有业务数据都归属某个店铺。
- 商品（Product）：属于某个店铺。有名称、类目、价格、描述等信息，支持变体。
- 商品变体（ProductVariant）：属于某个商品。表示颜色、尺寸等组合，每个变体有 SKU 编码。
- 文案版本（ProductCopy）：属于某个商品。一次 AI 生成或一次人工修改产生一个版本，记录内容和语言。
- 商品图片（ProductImage）：属于某个商品。图片文件本体存本地目录（public/generated/），记录只保存文件相对路径、用途（主图 / 详情图 / 变体）、生成提示词、是否已应用到商品、显示顺序；图片文件本身不存进数据库。
- 视频脚本（VideoScript）：属于某个店铺，可关联某个商品。有类型、时长、分镜内容、钩子、CTA。
- 直播脚本（LiveScript）：属于某个店铺。有时长、商品列表、流程节点。
- 对话（Conversation）：属于某个店铺。一次连续对话，有标题和时间。
- 消息（Message）：属于某个对话。有角色（用户或 Agent）、内容、时间。
- 记忆条目（MemoryEntry）：属于某个店铺。分类存储店铺画像和用户偏好，支持编辑和删除。
- 生成审计（Generation）：属于某个店铺。每次 AI 调用留一条记录，含输入、输出、模型、时间。
- Agent 技能（Skill）：可复用的技能模板，不属于特定店铺，存于文件系统，可启用 / 禁用。

对象关系：

```
Shop
 ├── Product ──── ProductCopy
 │        ├── ProductVariant
 │        └── ProductImage
 ├── VideoScript
 ├── LiveScript
 ├── Conversation ──── Message
 ├── MemoryEntry
 └── Generation
```

- 所有业务对象以 shopId 为隔离键。
- 没有"用户"对象：本产品无账号体系，因此也没有 userId。
- 图片文件本体不存数据库：素材图片文件存在本地目录，ProductImage 只保存文件路径与档案信息，避免 SQLite 文件膨胀。
- 文案、脚本、记忆、技能均记录创建时间和修改时间。

## 第四层：页面清单与导航流程

### 4.1 页面清单

1. **API Key 引导页**：未配置 Key 时首次打开的唯一页面。包含填写框和获取 Key 的说明链接。
2. **店铺创建页**：数据库中无店铺时出现。包含店铺名称、所属市场、店铺简述。
3. **工作台主界面**：产品主页面。顶部店铺切换器；左侧对话列表；中部对话区（流式回复、工具状态卡、快捷指令）；右下角全局 Agent 入口。
4. **商品页**：商品列表 → 商品详情（含"文案历史"标签页，支持版本对比与切换）。
5. **脚本页**：视频脚本与直播脚本的列表和详情，可查看和修改。
6. **数据看板页**：展示 GMV、订单量、转化率、流量来源、内容表现等指标。
7. **设置页**：含五个板块——店铺管理（添加 / 编辑 / 归档）、模型与 API Key、Agent 记忆管理、技能管理、数据导出。
8. **全局侧边抽屉**：任何页面右下角唤出的 Agent 对话面板，不跳转当前页。

### 4.2 导航流程

首次使用：
启动脚本 → 自动打开浏览器 → localhost:3000 → 无 API Key → API Key 引导页 → 填写并保存 → 无店铺 → 店铺创建页 → 创建成功 → 工作台主界面（Agent 自动打招呼）

日常使用：
双击启动脚本 → 浏览器自动打开 → 已有 Key 且已有店铺 → 直接进入工作台（默认上次使用的店铺）

页面间跳转：
- 工作台 ←→ 商品页 / 脚本页 / 数据看板 / 设置页：顶部导航互跳，随时可返回
- 商品页 → 商品详情 → "文案历史"标签页
- 任何页面 → 侧边抽屉（Agent 对话）
- 设置页 → 店铺管理（添加 / 编辑 / 归档）→ 返回设置页
- 店铺切换：任意页面顶部下拉切换 → 当前页面数据刷新为新店铺，对话上下文切换为新店铺

## 第五层：技术偏好与约束

### 5.1 技术栈

- 前端 + 后端：Next.js 14（App Router），后端接口用 Next.js Route Handlers；界面用 shadcn/ui + Tailwind
- Agent：Pi Agent Harness SDK 嵌入模式
- 数据库：SQLite + Prisma ORM（本地单文件，零配置）
- 交付：三个平台的启动脚本（`启动.bat` / `启动.command` / `start.sh`），内置环境检测；开发者备选命令行方式（git clone + npm install + npm run dev）

### 5.2 AI 模型

- 主推理与文案 / 脚本生成：deepseek等兼容模型，用户自备 API Key，通过本地配置文件切换
- 图片生成：gpt-image 2，作为独立工具调用
- 记忆提取：deepseek，在对话结束时提取关键信息，控制成本

### 5.3 约束（必须满足）

性能：
- Agent 首字响应 < 2 秒
- 完整文案生成 < 15 秒
- 选品报告（含 MCP 数据查询）< 30 秒
- 页面加载 < 2 秒
- 空闲时内存 < 500MB，CPU 占用 < 5%

安全：
- API Key 只存服务端本地配置文件，前端浏览器无法读取
- Agent 系统提示词不可被对话内容读取或修改
- 除 LLM API 调用和 MCP 数据查询外，不向任何外部服务发送数据
- 文档明确告知：若部署机器的地址可被他人访问，通过防火墙 / VPN 控制访问

可用性：
- 界面全中文；所有错误有中文提示，不出现白屏或英文报错
- 所有列表页无数据时有引导性提示
- 所有异步操作有加载指示器
- Agent 生成的内容按目标市场使用对应语言
- 数据持久化：关闭并重启后所有数据仍在（存于本地 SQLite 文件）

离线：
- 断网时工作台的管理功能正常可用
- Agent 对话显示"无法连接 AI 服务"错误提示

边界：
- 外部数据源通过 MCP 协议接入，不改 Agent 核心
- 领域知识以 .md 文件存放，对话时本地检索、只把相关片段注入提示词（轻量 RAG），不全量写入系统提示词，控制 token 成本与上下文长度
- 新增技能以文件形式加入；切换模型只改本地配置
- 无插件市场，无运行时动态安装扩展
- 产品本身免费开源，不使用任何付费第三方 API；AI 费用由用户自己的 Key 按实际调用量承担

### 5.4 开放问题

| 问题 | 影响 | 建议 |
|------|------|------|
| MCP 数据平台的协议和接口未确定 | 选品和竞品工具的实现 | 先定义工具的输入输出接口，MCP 实现后对接 |
| 中国大陆网络访问 LLM 可能受限 | API Key 可能无法直连 | 文档中说明：用户自行解决网络问题，或使用兼容 API 的国内模型 |
